# 2026-09-17 — Sibuyan Alert

## Shipped: reach tracking (unique viewers per incident and per risk zone)

Option 1 of the design discussion in `2026-09-16.md`: "how many distinct people opened this
record's details", with risk zones included in the same mechanism. Full design, sizing
calculation and Data Privacy Act mapping are in **`docs/view-reach.md`** — that file is the
reference, this is the change record.

### Server

- **`server/models/ViewEvent.js`** (new) — collection `view_events`, one row per
  `(targetType, targetId, viewerKey)`. Polymorphic (`report` | `zone`) so incidents and zones
  share one dedupe rule. Three indexes: `uniq_target_viewer` (unique — THE dedupe),
  `ttl_last_viewed` (TTL, `VIEW_EVENT_RETENTION_DAYS = 180`), `reach_by_type_recent`.
- **`server/services/viewEventService.js`** (new) — `buildViewerIdentity`,
  `recordViewEvent` (upsert + one retry on E11000), `readReachByTargets`, `readTopReach`.
  No exported function can return a per-viewer list; that is a design constraint, not an
  accident.
- **`server/controllers/viewController.js`** (new) — `recordView` (POST /api/views) and
  `getReachLeaderboard` (GET /api/views/reach). Also keeps the legacy `Report.viewCount`
  counter alive so Accident History's "Views" column does not freeze.
- **`server/routes/views.js`** (new), mounted at `/api/views` in `server.js`.
- `reportViewLimiter` renamed to **`viewLimiter`** (it now serves both target types).
- `analyticsController.getAdminAnalytics` gained a scoped `reach` block.

### Client

- **`client/src/utils/viewerIdentity.js`** (new) — opaque `localStorage` uuid, with a manual
  RFC 4122 v4 fallback because `crypto.randomUUID` needs a secure context and this app is
  reachable over plain-HTTP LAN.
- **`client/src/hooks/useRecordView.js`** (new) — fire-and-forget, once per target per mount.
- **`client/src/hooks/useReachData.js`** + **`components/dashboard/ReachPanel.jsx`** (new) —
  the admin display, wired into `DashboardAnalyticsWorkspace`.
- Instrumented: `MapIncidentDetails` (report), `HighRiskZoneDetails` (zone),
  `AccidentHistoryPage` (migrated off `api.recordView`, which was then deleted).
- `api.recordViewEvent` attaches the anonymous id centrally so no surface can forget it.

### Two traps worth remembering

1. **Fake timers defeat a production timeout.** `getAdminAnalytics` bounds its reach lookup
   with a 2s `Promise.race` so a stalled aggregation cannot hang the endpoint. But
   `adminAnalyticsAccuracy.test.js` calls `vi.useFakeTimers()`, so that timer never fires and
   the real (unmocked) `ViewEvent.aggregate` hung all six tests for 60s. Fixed by mocking
   `ViewEvent` in that test with `importOriginal` so the real constants survive. The timeout
   is still correct for production — it just cannot be the thing that saves a fake-timer test.
2. **A fire-and-forget hook must not be able to throw.** The first `useRecordView` called
   `api.recordViewEvent(...).catch(...)` — but four client test files mock the api module
   without that new method, so the call threw *synchronously* inside the effect and took the
   panel down with it: **55 client tests failed**. Fixed with `?.` plus try/catch in the hook,
   which is also what its own doc comment promised. Telemetry must degrade, never break.
