## Codebase analysis pass — Sibuyan Alert (read-only, no code changes)

Performed a full end-to-end architecture read-through to explain how the system works.

**Core process (incident lifecycle):**
`pending` → (municipal admin verifies/rejects) → `verified` → (responder declares en route) → `responding` → `resolved`.
Plus a lateral `transferred` state (two-step transfer + acknowledge) for out-of-jurisdiction reports.

**Key findings worth remembering:**

- **Report status enum** lives in `server/models/Report.js`:
  `['pending', 'verified', 'transferred', 'responding', 'resolved', 'rejected']`.
  Only `pending` may be verified/rejected — re-verifying a downstream report returns **409**
  (`adminController.verifyReport`). This guard is deliberate: prevents duplicate alerts + state corruption.

- **Responding IS the acknowledgement.** `respondToReport` calls `acknowledgeDispatch()`.
  A second unit joining must NOT overwrite the first ack time (it is the audit record of wait duration).

- **Dispatch escalation** (`server/services/dispatchEscalationService.js`) exists because SMS is out of
  scope — silence had to be treated as failure. Ack deadline is armed in the *same* `save()` as the
  status change, so there is no window where a verified report has no deadline.
  Concurrency safety = single atomic `findOneAndUpdate` claim (no locks, no leader election, no timers).
  Deliberately a polling sweeper, not per-incident timers (timers die on dyno recycle).
  Budget exhaustion sets `nextEscalationAt = null` → stops retrying, stays flagged.

- **Socket room naming is inconsistent by design and matters:**
  `municipality_${municipalityName}` (name) is used for admin/local rooms, but
  `broadcastVerifiedReportToResponders` is called with `report.municipalityName`.
  Client-side `server.js` room joins use `assignedMunicipality` (a name string). Watch this if rooms ever misbehave.

- **Auth:** no localStorage tokens. Three cookies — `sibuyan_jwt` (access), `sibuyan_refresh`, `sibuyan_csrf`
  (double-submit). Access-token refresh is a single-flight promise with a `SESSION_ROTATING` retry
  ladder `[100, 250, 500]ms` in `client/src/services/api.js`. Max 5 concurrent sessions
  (`MAX_ACTIVE_SESSIONS`), excess revoked with reason `session_limit`.

- **No super-admin by design.** Every admin/responder is scoped to `assignedMunicipality`
  (Cajidiocan | Magdiwang | San Fernando). `ensureReportScopeAccess` / `ensureUserScopeAccess` enforce it.

- **Geo discipline:** Sibuyan bbox `lat 12.30–12.55`, `lng 122.45–122.70`. Coordinate→barangay uses
  `$geoIntersects` on official polygons. Ambiguous matches are left **unassigned** rather than guessed
  (both in `Report.pre('save')` and the boundary service).

- **SWR cache** (`client/src/utils/queryCache.js`) is the single data layer. Keys must be scoped per
  municipality/user (`dashboard:operational:{muni}` etc.). Explicit Retry/Refresh must pass `{ force: true }`.
  `clearQueryCache()` runs on logout and in `test/setup.js`.

- **Registration is fail-closed:** both `idDocument` + `selfiePhoto` required; face detector failure
  returns **503** and never creates the user.

**Dead code noticed (not touched):** `client/src/test/tmp-*.test.js*` — 7 leftover scratch test files
(`tmp-ReportPage`, `tmp-offlineReportQueue`, `tmp-probe-direct`, `tmp-probe-globals`,
`tmp-sync-integration`, `tmp-useOfflineReportSync`, `tmp-writeahead`). Candidate for cleanup if tests
are ever re-inventoried.

## Risk-zone pinning accuracy audit (`/admin/zones`) — read-only, no changes made

User reported: cannot tell if a high-risk-zone pin is accurate — no identifying layers on the map,
and it stays blurry even at max zoom. Root causes found in code:

1. **Zoom hard-capped at 16.** `client/src/config/mapProvider.js:11` `OPERATIONAL_MAX_ZOOM = 16`
   (comment: z17 excluded, production imagery coverage incomplete). Enforced twice in
   `components/map/MapView.jsx` — `maxZoom: OPERATIONAL_MAX_ZOOM` at :647 and
   `map.setMaxZoom(OPERATIONAL_MAX_ZOOM)` at :949. At z16 ≈ **2.33 m/px** on Sibuyan
   (156543.03 × cos(12.4°) / 2^16), so a pin is realistically ±10–25 m off — material when the
   default zone radius is **100 m**.

2. **Street basemap not configured.** `client/.env` has `VITE_PMTILES_URL` commented out;
   only `VITE_3D_LABELS_PMTILES_URL=/maps/sibuyan.pmtiles` is set. Asset exists at
   `client/public/maps/sibuyan.pmtiles` (871 KB) and ships to `dist/maps/`. Consequence in
   `mapProvider.js`: `prepareOperationalMapStyle()` is called with **no options** (`MapView.jsx:530`)
   → `includeStreet` defaults true → with 3D labels present `hasVectorLabels = true`, so
   `esri-reference-layer` is hidden at build time (:359) — but `MapView.jsx:948-958` re-shows the
   3D vector labels in satellite mode. Net: imagery + a sparse vector label subset, no street vectors.
   **Bug:** `mapProvider.js:390-392` returns `OPERATIONAL_MAX_ZOOM` (16) as `streetMaxZoom` when no
   street PMTiles exists, so the OSM raster fallback (source declares `maxzoom: 19`, :292) is also
   capped at 16 even though OSM has real detail at 17–19.

3. **Barangay polygons never reach the client.** `server/services/barangayBoundaryService.js` exports
   only `resolveBarangayForCoordinates` + `getActiveBarangayBoundaryCount`. `grep -rn "boundar" routes/*.js`
   → **zero hits**. No route serves the polygons, so the click is validated server-side and reported
   only via a toast ("Location verified in X") — the boundary line is never drawn.

4. **No scale bar.** Only `NavigationControl` is added (`MapView.jsx:666-677`); no `ScaleControl`
   anywhere under `components/map/`. Zone size is metric (`radius` 10–5000 m, default 100,
   `AdminHighRiskZonesPage.jsx:52`) with no metric reference on screen.

5. **Coordinates shown to only 4 decimals** (`AdminHighRiskZonesPage.jsx:649`, `toFixed(4)`)
   ≈ 11 m precision.

6. **Zone = point + radius circle**, not a polygon — accuracy is entirely the epicenter.

7. `Report` has **no `2dsphere` index** (only compound `coordinates.lat`/`lng`, `models/Report.js:387`),
   so any radius query must use a bbox pre-filter like `utils/duplicateDetection.js` does.

**Recommended order:** (1) ScaleControl + crosshair/live coords + 5–6 decimals; (2) uncap street
zoom to 19 when no street PMTiles; (3) serve + draw simplified barangay boundaries; (4) overlay
resolved/verified incidents as the evidence for "where is it actually dangerous"; (5) ESRI
World Hillshade underlay for landslide-prone slope reading.

**Framing that matters:** don't fight the imagery. ESRI z16 over Sibuyan is what it is (Sentinel-2
at 10 m/px would be worse, not better). Accuracy should come from **vector reference geometry**
(boundaries, scale, incident history), not from pixels.

## GIS landslide hazard research + Sibuyan extract (DELIVERED)

User wanted a real GIS hazard layer identifying possible landslide areas, not a visual reference.

**Source found (free, authoritative, usable):**
`https://huggingface.co/datasets/bettergovph/project-noah-hazard-maps` — BetterGovPH mirror of
**DOST Project NOAH** hazard maps. Derived from **1 m LiDAR + 5 m IfSAR DEM**; models = Matterocking,
Conefall, SINMAP, Flow-R. **License: ODC-ODbL** (attribution + share-alike on derivatives).

Datasets in the repo: `Landslide/LandslideHazards/<Province>.zip` (shapefiles), `Flood/{5,25,100}yr/`,
`Storm Surge/StormSurgeAdvisory{1-4}/`, `Landslide/DebrisFlowAlluvialFan/`, plus prebuilt
`PMTiles/layers/*.pmtiles` (landslide.pmtiles is 2.8 GB nationwide; flood_100yr 1.0 GB;
debris_flow 20.6 MB). Sibuyan is in **Romblon** → `Landslide/LandslideHazards/Romblon.zip` (45.6 MB).

**Gotchas that cost time:**
- The published `metadata_landslide.txt` says the field is **`HAZ`** with values 1/2/3. The actual
  shapefile field is **`LH`** (float, 19/11). Trust the file, not the doc.
- The shapefile has only **3 records** — one dissolved multipolygon per hazard class, but with
  enormous part counts (LH=1: 192,887 parts / 1.55 M pts; LH=2: 26,879 / 1.06 M; LH=3: 3,324 / 180 k).
- **`shapely.union_all` / global `intersection` on the whole record OOMs (SIGTERM).** Must work
  **per-part**: bbox-reject each part, then clip + simplify that single small polygon. Cheap.
- Name your script anything but `inspect.py` — it shadows stdlib `inspect` and breaks numpy/shapely import.

**Delivery recipe that worked (per-part clip + simplify):**
bbox filter → `Polygon(ring)` → `buffer(0)` if invalid → `.intersection(SIBUYAN_BBOX)` →
`.simplify(0.0003, preserve_topology=True)` → round to 6 dp → MultiPolygon per hazard class.

**Measured size budget (Sibuyan bbox 122.45–122.70 / 12.30–12.55):**

| Classes | Tolerance | Raw |
|---|---|---|
| 1+2+3 | 11 m | 5.38 MB |
| 2+3 | 11 m | 1.43 MB |
| 1+2+3 | 33 m | 4.40 MB |
| **2+3** | **33 m** | **0.93 MB (232 KB gzipped)** |
| 2+3 | 67 m | 0.69 MB |

**Chosen: medium + high only, ~33 m** → 877 high polygons + 5,705 medium polygons, 41,761 points.
Dropping class 1 (low) removes 37,601 parts = 85% of the payload for the least actionable class.
Bbox 122.45–122.70 contains **only Sibuyan** within Romblon (Tablas/Romblon I./Corcuera/Banton all
sit west of 122.45), so a bbox filter needs no island masking.

**Also checked and REJECTED:** PHIVOLCS ArcGIS (`https://gisweb.phivolcs.dost.gov.ph/arcgis/rest/services`)
— has `PHIVOLCSPublic/*` MapServers with **CORS open** (`Access-Control-Allow-Origin` reflects Origin)
but the only landslide service is **earthquake**-induced, not tiled, and its `/0/query` returns
"operation is not supported". The **`MGB` folder returns 499 Token Required** → not publicly usable.
NOAH rain-induced (what we want) has no public tile service — the HF shapefile mirror is the way in.

**THE BIG FINDING — there is no flood data for Sibuyan.**
The Romblon flood archive (`Flood/100yr/Romblon.zip`) bbox is 121.68–122.33 — Tablas and Romblon
Island only. **0 of 25,426 polygons** intersect the Sibuyan bbox. Cause, per `metadata_flood.txt`:
NOAH flood LiDAR covers only the **18 major river basins**, and Sibuyan is not one. Also the 5yr and
25yr archives are **not mirrored for Romblon at all** (`Flood/5yr/Romblon.zip` → 15-byte
"Entry not found"). So `flood_prone` has no NOAH polygons behind it for Sibuyan — the admin can
