**Key finding — doc drift.** `CODEBASE_CONTEXT.md` (1497 lines) documents the system
well but has fallen behind the code. Undocumented-in-doc modules that ARE live:

Server-side:
- `services/dispatchEscalationService.js` — ack-clock arming + atomic-claim escalation
  sweeper. The ONLY background timer in the app. 30s sweep, 5min ack window,
  5min escalation interval, max 3 escalations, batch 25. Atomic `findOneAndUpdate`
  claim = multi-dyno safe without leader election.
- `services/backgroundTaskQueue.js` + `services/evidenceProcessingQueue.js` — in-process
  FIFO queues. Evidence queue exists because face-detection of 5 photos could hold a
  request ~90s, past Heroku's 30s router timeout. Concurrency deliberately 1.
- `services/previewService.js` — blurred SVG privacy fallback (640x480).
- `services/viewEventService.js` + models `ViewEvent.js` / `ViewerAlias.js` — the "reach"
  feature (distinct viewers per record). Dedup via unique index, 180d TTL.
- `config/dispatchPolicy.js`, `config/queryPolicy.js` (maxTimeMs 5000, page 50/100,
  cache TTLs), `config/scaling.js` (refuses prod boot with WEB_CONCURRENCY>1 sans REDIS_URL).
- `utils/apiCache.js` (500-entry in-proc cache-aside + in-flight dedup), `utils/httpCache.js`
  (weak ETag / 304), `utils/concurrency.js`, `utils/duplicateDetection.js`
  (60min / 250m / max 5 candidates), `utils/accidentHotspots.js` (100m radius, 30d window,
  medium 3 / high 6).

Client-side:
- `hooks/useOfflineReportSync.js` + `utils/offlineReportQueue.js` — IndexedDB write-ahead
  queue (`sibuyan-offline`), idempotent via `clientReportId`, exponential backoff
  15s→×2→300s cap, transient vs permanent failure classes, POSSIBLE_DUPLICATE parking.
- `utils/reportDraft.js` — localStorage `sibuyan-report-draft-v1`, 7-day TTL, never stores photos.
- `hooks/useConnectivity.js` (interface state) + `hooks/useSystemHealth.js` (`/api/health`, 60s poll).
- `hooks/useReachData.js` + `hooks/useRecordView.js` + `utils/viewerIdentity.js`
  (localStorage `sibuyan.viewerKey`, anon uuid v4; deliberately not IP/MAC).
- `services/serviceWorker.js` — cache-scope isolation so a logged-out device cannot read
  the prior account's cached incidents.
- `utils/lazyWithRetry.js` (stale-chunk recovery, 1 auto-reload/session, 10min guard),
  `utils/blobCache.js` (50-entry LRU, single-flight), `utils/progressThrottle.js` (250ms).
- `hooks/useSelfieFaceDetection.js` + `utils/selfieFaceDetector.js` — on-device only,
  100ms scan, 2200ms stability to auto-capture, 2500ms cooldown, 320px scan dimension.

**Architecture confirmations from source (not docs):**
- `server/server.js` is the real boot sequence: trust proxy(1) in prod → CORS → compression
  (threshold 1024) → json 10mb → security headers → CSRF → routes → SPA → error handler.
- Startup order: `validateRuntimeConfig` → Redis adapter → `connectDB` → `initFaceDetector`
  warm → seeds → boundary/hazard readiness checks → analytics view → escalation sweeper.
- Socket rooms are joined server-side in the `join` handler from the cookie identity
  (user_, reporters, municipality_, municipality__responders). Presence tracking removed.
- `/api/health` deliberately surfaces `boundaries.ready` + `hazardLayers.ready` because a
  missing dataset would otherwise render as "no hazard here" = a false all-clear.
