## Analytics dashboard — reporting scope control (Monthly / Yearly / All time)

**Task:** the user reported that Monthly/Yearly/All time rendered as concatenated plain text,
and that All time still showed a "Reporting period" label + calendar + picker.

**Key finding first:** the scope control **did not exist** in the app. The only place it
existed was `scratch/analytics-scope-controls-preview.html` (untracked, gitignored, written
19:42 today). Verified by `grep -rn "All time|All-time|allTime"` over `client/src` + `server`
(only static labels in `ResponderDashboardWorkspace.jsx:278` and `AdminPage.jsx:512`),
`grep -ril "yearly"` (zero hits), and `DashboardAnalyticsWorkspace.module.css` having
`.periodControl`/`.periodButton` but no `.scope*`. Also absent from `main`, `clumsy-feet`,
and `restore-latest`.

I asked instead of guessing (two questions). User chose: **"Build it fresh"** (implement the
preview design in the real component) and **"Scope filters the data"** (Yearly/All time
genuinely filter, accepting new props from DashboardPage).

### What was built

- **`client/src/utils/analyticsTrend.js`** — added `ANALYTICS_SCOPE`, `getManilaYearKey`,
  `buildMonthlyIncidentTrend` (12 month buckets, stops at the month in progress),
  `buildYearlyIncidentTrend` (one bucket per year, earliest → current, quiet years kept as
  gaps), `buildPeriodIncidentTrend` (dispatcher), `filterReportsByPeriodKey` (day/month/year
  key by scope). `getTrendInsight` gained an optional `prevLabel` so the delta can read
  "3 more than 2025" instead of only month names. All existing exports/signatures preserved.
- **`client/src/pages/DashboardPage.jsx`** — added `analyticsScope` + `selectedYear` state;
  `monthFilteredReports` became `periodReports` (one filter point — every panel, metric,
  breakdown, the map and the export read it); `chartData` now comes from
  `buildPeriodIncidentTrend`; new props passed down.
- **`client/src/components/dashboard/DashboardAnalyticsWorkspace.jsx`** — new toolbar:
  segmented scope control (Scope label + bounded track), scope-conditional picker
  ("Reporting month" / "Reporting year"), **no period UI at all in All time**, export in its
  own cell with a rule only while stacked. Scope-aware copy throughout (header subtitle,
  overview meta, trend description/aria-label/empty state, lifecycle, map heading, select
  labels). `SCOPE_OPTIONS`, `SCOPE_TREND_COPY`, `SCOPE_MAP_HEADING` hold the wording.
- **`...module.css`** — `.scopeControl`, `.scopeButton`, `.scopeButtonActive`, `.scopeIndicator`.

### Decisions worth remembering

- **`aria-pressed` on plain buttons inside `role="group"`, NOT `role="tablist"`/`radiogroup`.**
  This is the app's own convention (`MapFilterRail`/`MapRailTab`), it exposes selection to AT,
  and it avoids a half-implemented tab/radio keyboard contract. The approved preview used
  `role="tab"`, which has no `aria-controls` panel to point at.
- **Selection is not colour-alone:** raised surface + 1px ring + `font-weight: 600` +
  a check glyph. The indicator span is width-reserved so switching scope cannot shift layout.
- **Below `sm` the scope buttons are `flex: 1 1 0`** so they split a full-width track equally.
  First pass had them content-sized and left-packed in a stretched full-width track (measured
  257px of buttons in a 472px track) — fixed after measuring.

### Tooling notes for next time (important)

- **Headless Edge/Chrome cannot render a viewport narrower than ~504px** via `--window-size`.
  To get a true 320/375px render, wrap the harness in an `<iframe width="320">` — media
  queries inside an iframe evaluate against the iframe viewport. See
  `scratch/analytics-scope-widths.html`.
- Measuring beats eyeballing: the harness takes `?debug=1` and dumps
  `{viewport, rowWidth, controlWidth, overflowsRow, buttons[]}` into a `<pre id="measurements">`,
  read with `--dump-dom` + `sed`. That is how the mobile overflow was found.
- Verify CSS-module changes against the **built** CSS, not the source: hashed names are
  `_<local>_<hash>_<lineNumber>`, so the line number changes on every edit above it. Rebuild
  and re-grep: `grep -o "_scopeControl_[A-Za-z0-9_-]*" client/dist/assets/DashboardAnalyticsWorkspace-*.css`.
- A `vite build` launched while `npm run test:client` was still running failed with a rolldown
  error; a clean re-run succeeded (EXIT=0, 10.3s). Do not run build and the full suite
  concurrently on this OneDrive-backed repo.

## Insights layout: cap, rebalance, bar cap, thin-trend list

**Task:** the Incident trend / Report lifecycle section stretched across the full 1500px
workspace on wide desktops, the trend took 2 of 3 columns, and Yearly/All time with few
points drew oversized bars in a mostly empty plot.

**Measured before changing anything** (harness below): at 1890px viewport the section was
1500px and the trend panel 1000px. The known-good width is documented in the file's own
comment as ~640px at xl.

### What changed (`DashboardAnalyticsWorkspace.jsx` only — no CSS module change needed)

- Section: `grid xl:grid-cols-3` → `mx-auto grid w-full max-w-6xl xl:grid-cols-5`.
  Cap **1152px**, centred. Measured: section 1152, **trend 690 / lifecycle 460**.
  The cap binds above ~1456px viewport (304px of chrome from lg: 240 sidebar + 2×32 padding).
- Split rebalanced 2:1 → **3:2** (`xl:col-span-3` / `xl:col-span-2`). At the cap the
  lifecycle now gets 460px instead of 384px; at xl (976px content) it gets 390px instead
  of 314px — the width the original comment complained was "narrower than its own rows".
- `maxBarSize={56}` on every severity Bar. Measured rendered bar widths:
  **All time 3 years 81px → 56px capped**; Yearly 12 months 20px and Monthly 31 days 7px —
  the cap never binds for those, so Monthly is untouched.
- `isThinTrend` = non-monthly scope with ≤2 active buckets → renders the **existing** compact
  period list (period, count, drill-down) instead of a near-empty plot. `isSparseTrend`
  (monthly) is unchanged; both now feed `isCompactTrend`.
- Loading skeleton updated to the same cap and 3:2 split so cards don't jump on load.
- `sr-only` summary now says "Reports by active {bucketNoun}" instead of always "day".

### Bug found and fixed while testing

The compact list keyed `<li>` on `day.dayKey` alone. The yearly scope now routes 1-active-bucket
data into that list, and the test fixture's `chartData` had no `dayKey` → React duplicate-key
warning. Fixed both ends: `key={day.dayKey || index}` (matching the sibling chart Cells) and
added `dayKey` to the `baseProps.chartData` fixture.

### Verification

- **114 files / 1231 tests passing** (was 1227; +4 new). Lint 0/0.
- New tests: cap + centring classes, 3:2 col-spans, `maxBarSize === 56` on every Bar
  (required recording Bar props through the recharts mock — `maxBarSize` is consumed
  internally so it is otherwise invisible), thin Yearly list with working drill-down, and a

- Width sweep measured with the harness: 1890/1570 → capped 1152; 1410 → 1096; 1250/1150/994/
  870/738 → stacked full width. Monthly at 1370 → trend 632, bars 7px. Mobile 320/375/414 →
  full width, stacked, no horizontal scroll.

### Remaining layout limitation (report, do not silently fix)

Below `xl` the two panels stack, so at a ~1250px viewport the trend plot is **~954px** — wider
than the 690px it gets at 1920px. That inversion is inherent to the pre-existing "split starts
where it fits at xl" decision (splitting at lg would give the trend 432px and the lifecycle
288px, the case the original comment explicitly rejected). `maxBarSize` keeps it from looking
wrong, but the inversion is real.

### Harness (reusable — this is the pattern to repeat)

`scratch/insights-layout-verify.html` renders the real grid classes and a **real recharts
chart** (loaded from `esm.sh`), with `?scope=`, `?cap=off`, `?years=3`, and a ruler line that
prints `viewport · section · trend · lifecycle · maxBarSize · rendered bar widths[]`.
Read it with `--dump-dom` + sed — do not eyeball screenshots for geometry.
`scratch/insights-widths.html` wraps it in iframes at 320/375/414 because headless cannot
render a viewport narrower than ~504px.
Gotcha hit twice: ResponsiveContainer renders a tick after mount, so the measurement must
**poll** for `.recharts-rectangle` instead of measuring in a `requestAnimationFrame`.
