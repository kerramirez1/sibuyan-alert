# 2026-10-31

## GPS auto-capture still erroring — current state + remaining failure modes

The two-phase acquisition recommended on 2026-10-18 IS applied: `ReportPage.jsx:621`
(coarse `getCurrentPosition`, `enableHighAccuracy: false, timeout: 6000, maximumAge: 60000`)
and `:627` (high-accuracy `watchPosition`, `timeout: 10000, maximumAge: 0`), watchdog at `:566`
(12s). `ReportPage.test.jsx:398` pins the coarse options exactly, so changing them breaks a test.

Remaining causes of "error kahit may signal", all verified in code:

1. **Out-of-bounds fix is silently dropped** (`ReportPage.jsx:578`). `applyPosition` returns without
   any feedback, `bestLocation` stays null, and 12s later the watchdog says "Could not determine
   location". The GPS worked; the point was outside the island envelope. This is the cleanest
   explanation for a timeout with signal. `ReportPage.test.jsx:441` pins the "drop it" behaviour but
   does NOT assert the absence of a toast, so adding a message is safe.
2. **A low-accuracy fix is discarded at the watchdog** (`:551-564`). If `bestLocation` exists but
   accuracy > `GPS_MAX_ACCURACY_METERS` (100), the code clears `selectedLocation` and errors. On a
   rural 3G link the coarse network fix is often 1000-5000m, so the reporter gets an error despite
   having a position. `ReportPage.test.jsx:398` shows a 1500m coarse fix IS applied to the form, so
   only the watchdog rejects it.
3. **No permission pre-check.** A permanently denied permission fails every attempt; the toast
   disappears and gives no instruction.
4. **`QueuedReportLocationFix.jsx:152` still uses `enableHighAccuracy: true, maximumAge: 0,
   timeout: 15000`** — the same options the ReportPage fix removed.

Performance levers, in order of perceived value:
- Permission pre-check (removes a guaranteed 12s failure).
- A visible "Use this location" action as soon as a usable fix exists, instead of always waiting
  the full watchdog — currently only <=30m stops early.
- On accuracy rejection, focus the map on the rejected fix instead of clearing everything, so the
  reporter can drag the pin from roughly the right place.

### FIX APPLIED — honest GPS failures

`client/src/pages/ReportPage.jsx` + `client/src/components/reporterReports/QueuedReportLocationFix.jsx`:

1. `sawOutOfBoundsFix` flag beside `bestLocation`; the bounds check in `applyPosition` sets it and
   still returns (detection is NOT aborted — a watch can deliver a transient bad fix first). The
   watchdog's `!bestLocation` branch now chooses between "outside Sibuyan Island" and the generic
   message.
2. Accuracy-rejection branch keeps the position: `setFocusLocation({ ...bestLocation, zoom: 13 })`
   was added. `selectedLocation` stays null on purpose — that field is what makes step 1
   submittable, so a coarse fix must not become the report's coordinates.
3. `detectLocation` is now `async` and pre-checks `navigator.permissions.query({ name: 'geolocation' })`
   after claiming `locationDetectionActiveRef` (so a double tap cannot start two acquisitions) and
   after `stopLocationDetection`. A `denied` state clears the flag, shows an actionable message and
   returns without ever calling `getCurrentPosition` / `watchPosition`.
4. `QueuedReportLocationFix.jsx`: `maximumAge: 0` → `30000`.
